# 公开档案隐私与资料分级规范

**当前仓库：PUBLIC（公开）。** GitHub 的子目录没有独立隐私权限。把文件放在 `private/` 文件夹并不等于私密；即使删除已提交的文件，也可能留在提交历史里。

## 可以放在此仓库

- 无敏感信息的个人职业定位、创意理念和工作偏好；
- 自己总结的通用技能方法与公开可验证的行业案例；
- 空白的项目、学习、决策模板；
- 经确认允许公开的本人作品与资料链接。

## 不应放在此仓库

- 电话、私人邮箱、证件号、住址、账号令牌；
- 未经客户明确授权的 Brief、合同、报价、供应商成本、内部沟通和名单；
- 尚未公开的品牌策略、商业目标、客户资料、项目图片或视频；
- 任何他人的私人数据、敏感健康或财务信息；
- 需要登录、付费或受版权限制的原始资料副本（未经授权时）。

## 私有仓库也不是万能保险箱

私有仓库限制普通公众访问，但仍可能受到协作者权限、第三方应用授权、账号安全和平台服务的影响。不要把密码、密钥和极敏感个人数据直接存为普通文本。建议开启双重验证，并定期检查 GitHub App 权限。

## 发布前的四步审核

1. 该内容属于自己的资料吗？是否有公开授权？
2. 是否含人物、公司、金额、内部流程等可能识别或造成商业风险的信息？
3. 是否真的需要公开？可以用总结、脱敏或仅保留方法论代替吗？
4. 发布后，即便删掉 GitHub 页面，历史版本是否仍会构成风险？

不确定就**不提交到公开仓库**。

## AI 工具边界

- 仅授权可信的工具读取必要文件，并注意其数据处理规则。
- 未明确要求时，不将私有档案复制到公开回答、仓库或对外材料。
- GitHub 文件不会自动变成所有 AI 产品的跨平台永久记忆；只有读取/连接文件的工具才能使用其内容。
- 用户当次指令、项目最新 Brief 和可靠证据优先于可能过时的档案。
