# 交付前质量检查表｜AI 与本人共同使用

## 方案内容（必须）
- [ ] 说明了客户要解决的真实问题，不只是活动形式。
- [ ] 受众是谁、他们为何投入注意力和行动，逻辑明确。
- [ ] 已确认事实、外部证据、策略假设、待确认点有明确区分。
- [ ] 至少三种创意路径在**内容或参与机制**上有明显差异。
- [ ] 最终方案有清楚的内容起承转合、参与动作与留存成果。
- [ ] 案例来源真实可查，未编造品牌数据、奖项和执行效果。

## 落地风险（必须）
- [ ] 关键动线、人员、时间、场地、硬件、供应商与风险可解释。
- [ ] 预算数据说明是否为报价、估算或历史实际。
- [ ] 对不可执行或未经验证的部分明确提醒。
- [ ] 从甲方/创意总监/执行负责人三个视角进行反向质疑。

## 文案与视觉
- [ ] 没有空洞口号、重复套话、过重 AI 表达。
- [ ] 视觉符合具体品牌而非千篇一律的科技模板。
- [ ] 用户上传的 Logo/照片/原始信息没有被擅改。
- [ ] PPT 中文无乱码，关键文字可编辑，页面信息层级合理。
- [ ] 高清素材没有拉伸、裁切失真或伪 4K。

## 数据与隐私
- [ ] 没有泄漏个人联系方式、客户未公开项目、报价单与合同。
- [ ] 没有把私人资料提交到**公开** GitHub 仓库。
- [ ] 对外可引用的案例已核查授权。
- [ ] 已标注资料更新日期与可能过时的假设。

## 结论

**上线/交付条件**：所有「必须」项有可靠答案；未满足的项目逐条标明风险、负责人和修复方法。不要用“整体不错”替代质量判断。
